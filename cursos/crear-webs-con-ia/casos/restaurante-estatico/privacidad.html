Privacidad del ejemplo

Qué ocurre con los datos del formulario

Esta página documenta el comportamiento técnico del prototipo. Un restaurante real necesitaría una política adaptada a su identidad, servicios y jurisdicción.

Resumen

La web se ejecuta en tu navegador y no incluye analítica, publicidad, cuentas, cookies no esenciales ni una base de datos. El negocio, correo y teléfono son ficticios.

Formulario local

Al pulsar «Preparar solicitud», JavaScript lee los campos para crear un resumen visible y un enlace `mailto:`. El prototipo no realiza una solicitud de red, no guarda el contenido y no confirma ninguna reserva.

Usa siempre datos sintéticos durante el aprendizaje. No escribas alergias, datos sanitarios, información financiera ni otros datos sensibles.

Aplicación de correo

Si decides pulsar el enlace generado, el navegador intentará abrir la aplicación de correo configurada. A partir de ese momento, el tratamiento dependería de esa aplicación y del proveedor de correo. En este ejemplo el destinatario termina en `.example` y no es operativo.

Archivos y almacenamiento

El servidor local solo entrega archivos estáticos. El código no usa `localStorage`, `sessionStorage` ni IndexedDB. Al recargar la página, el contenido del formulario desaparece.

Antes de usar una versión real

  • Identificar responsable, finalidad, base aplicable y conservación.
  • Elegir un canal de reserva real y probar entrega, duplicados y fallos.
  • Minimizar datos y protegerlos durante tránsito y almacenamiento.
  • Crear procedimientos de acceso, eliminación e incidentes.
  • Revisar textos y obligaciones con asesoramiento apropiado.
